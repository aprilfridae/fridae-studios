# Studio mode: decisions made during the build

Every judgment call the coordinating session made while executing `2026-11-21-studio-mode.md`, in the order made, each with what it costs if wrong. Copied from the build ledger on 2026-11-21.

- Tasks | Item | Ruling

- T1↔T7 | stage done → checkpoint request | Ruling: T1's stage done does not write a checkpoint request; T7 adds it — cost: none
- T3↔T5 | "slots" note in studio.json written by the app | Ruling: T3 adds a small pure helper + test; file write goes through whatever T5 creates, so T3 writes studio.json directly with an atomic write and T5 reuses it — cost: small refactor

- T6 | "AI where helpers don't work" | Ruling: T6 asks the app (a field on the existing status/agents info) rather than hard-coding AI names; if no such signal exists, T5 adds "helpers": bool to the review/run response — cost: small
- Ruling: one lock per project for read-modify-write of studio.json and review items: lock file <project>/.fridae/.lock created with O_CREAT|O_EXCL (holder pid + time inside), retried up to ~5 s, taken over when older than 10 s; the Rust app (Task 5) uses the same file — cost if wrong: a stuck lock delays a write by ≤10 s
- Ruling: a gated stage is done only when it has at least one approved blocking item AND no blocking item of that stage is still waiting or changes (reviewer's minor promoted: the gate must not pass over an open blocking item) — cost: none

- Ruling: writer lock is in-memory in the app, keyed by project, released on finished() and when a helper is stopped or closed — cost: a crashed app forgets it (no helpers survive a restart anyway)

- Ruling: while a run is waiting, any user message or decision resumes it in Studio mode even without "studio": true (taken from last_ask) — a waiting run must not silently fall out of Studio mode — cost: to leave Studio mode the user presses Stop or picks another mode after it resumes

- Ruling: approve_all sends one wake message for the batch — cost: none

- Ruling: the watcher may emit studio_run for the app's own studio.json writes (the page needs the refreshed run after pause/settings anyway) — the "not for the app's own writes" decision applies to review items only — cost: one extra repaint
- Ruling: Task 6 start-from-chat rule — Studio + send in a project chat starts a run with that chat as Lead when the game has none; sends normally with studio:true when this chat is the Lead; refuses with a pointer to Review when another chat leads — cost: none
- Ruling: checkpoints must survive an app restart (everything undo needs on disk under .fridae/); the run's start is checkpoint "start"; undo leaves the run paused and archives review items filed after the checkpoint — cost: more disk under .fridae/
- Ruling: while paused, decisions and messages are recorded/queued but do not resume the loop; only Resume does; Stop on the Lead marks the run paused — cost: a user who types to a paused Lead must press Resume
- Ruling: Studio script snapshots stay in the plugin's memory (survive an app restart, not a Studio restart), as the night undo always did; files/stages/review items are on disk — persisting scripts to .fridae/checkpoints would be a second mechanism; documented limit, FLAG TO USER — cost: after closing Studio, undo restores project files but not unsaved-in-snapshot Studio scripts

- Ruling: before reverting Studio, undo pins a snapshot of the scripts as they are now ("before undo") so nothing is unrecoverable, and the confirm text says plainly that every script's text goes back, the user's and other chats' included — cost: one pin slot
- Ruling: when Studio is not connected and the run took any Studio snapshot (a checkpoint has studio: true), undo refuses with "Open the game in Roblox Studio, then undo — or undo the files only" and accepts files_only: true to restore project files alone, saying Studio was left as it is — never reports a Studio undo that did not happen — cost: one more click in that case

- Ruling: Task 8's live run is one short studio run on the user's default AI in a scratch work folder, capped at ~15 minutes of agent time; misbehaviour is reported as a finding, only small verified prompt fixes are in scope — cost: a few minutes of the user's AI plan

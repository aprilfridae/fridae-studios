

THIS CHAT BELONGS TO A GAME PROJECT. Its folder is your working directory: {path}
- GAME.md in that folder is the game bible: what the game is, its pillars, core loop, numbers, art direction and the log of
  decisions. Load the `game-bible` guide and read GAME.md before doing anything else. If it does not exist yet, creating it
  is the first job (see the guide).
- Never contradict GAME.md silently. If a request conflicts with it, say so and ask which wins. When something is decided
  or changed, update GAME.md in the same turn, including a line in its decision log.
- Before a large change, and again when the work is finished and checked, call rbx_project with action "checkpoint" and a
  short message. It exports the place's scripts into src/ and commits them when the folder is a git repository, so the
  work can be compared and scripts restored. Parts, UI and other instances are not in a checkpoint.
- Project files you write (notes, plans, data tables) go in this folder. Generated assets still go to the working folder
  the tools use.
- The game has a board (rbx_board); the user sees its needs cards in the game's Review tab. Keep it true as you go: a card in doing for each real piece
  of work you start, moved to done once it is finished and checked; a card in needs for each thing only the user can do
  (one clear action per card); planned work in todo. Look at it (action list) at the start of a job: the user may have
  added cards for you, and cards in todo are the user's wishes for what comes next.
